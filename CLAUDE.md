## Project Overview

Miyagi is a component development tool for JavaScript template engines (v4.x, ES module). It provides a dev server, static build generation, component scaffolding, mock data management, and design token extraction. Package manager is **pnpm**.

## Common Commands

```bash
pnpm install          # Install dependencies
pnpm build            # Build frontend assets (gulp: rollup JS + postcss CSS → dist/)
pnpm test             # Run vitest with coverage for api/ and lib/
pnpm lint             # Stylelint CSS + ESLint lib/ + ESLint frontend/assets/js/
pnpm fix              # Auto-fix ESLint issues
```

Run a single test file:

```bash
npx vitest run tests/lib/<file>.test.js
```

Pre-commit hooks run `lint` and `test` automatically.

## Architecture

### Core Layers

- **`lib/`** — Core library. Orchestrates everything: config loading, Express server, file watching, rendering, state management, static builds.
- **`api/`** — JavaScript API (`getMockData`, `getHtml`, `createBuild`, `createComponent`, `lintComponent`, etc.). Imported as `@miyagi/core/api`.
- **`bin/miyagi.js`** — CLI entry point using yargs. Commands: `start`, `build`, `new`, `mocks`, `lint`, `drupal-assets`.
- **`frontend/`** — UI assets (CSS, JS, views) for the dev server interface.
- **`dist/`** — Built frontend assets (generated by `pnpm build`).

### Key `lib/` Subdirectories

- **`init/`** — Server initialization: Express setup, router, watcher (WebSocket live reload), template engine registration.
- **`state/`** — Global state management (`global.state`, `global.config`, `global.app`). Tracks routes, source tree, file contents, partials, menu, components, CSS.
- **`render/`** — Renders views (main window vs iframe). Components always render in iframes.
- **`build/`** — Static build generation: produces HTML pages, copies assets, creates `output.json` manifest.
- **`mocks/`** — Mock data resolution. Supports `$ref` (cross-component references), `$tpl`, `$variants`, `$defs`.
- **`validator/`** — AJV-based JSON schema validation of mock data.
- **`generator/`** — Scaffolds new components and generates mock files from schemas.
- **`styleguide/`** — Design token extraction from CSS custom properties (colors, typography, spacings).
- **`drupal/`** — Drupal-specific utilities: parses `*.libraries.yml`, resolves dependency trees, maps libraries to component folders. Used by `miyagi drupal-assets` CLI command. Config via `.miyagi-assets.js` (engine-keyed structure).

### Component Model

Each component is a folder containing: template file (e.g. `component.twig`), `mocks.json` (JSON/JS/YAML), `schema.json`, optional `README.md`, `index.css`, `index.js`. Components support variants via `$variants` in mock data.

### Component Asset Isolation

By default all global CSS/JS (`config.assets.css/js`) are loaded for every component iframe. Components can opt into isolation by declaring `$assets` in `mocks.json`:

```json
{
	"$assets": {
		"css": ["button.css"],
		"js": [{ "src": "button.js", "type": "module" }]
	}
}
```

Config supports `assets.shared` (always loaded for isolated components) and `assets.isolateComponents` (forces isolation for all components). Resolution logic in `lib/render/helpers/resolve-assets.js`:

- Component has `$assets` → `shared + $assets`
- No `$assets` + `isolateComponents: true` → `shared` only
- No `$assets` + `isolateComponents: false` → all global assets (legacy)

### Configuration

User config via `.miyagi.js` or `.miyagi.mjs` (ES module). Must provide a custom render function (consolidate.js was removed in v4). Defaults in `lib/default-config.js`.

### Global State

The codebase uses `global.config`, `global.state`, and `global.app` extensively for shared state across modules.

## Code Style

- **ES modules** throughout (`"type": "module"`)
- **Prettier defaults** (spaces, double quotes, etc.)
- **Node >= 24** required
- ESLint with JSDoc plugin (warnings for missing docs)
- Separate ESLint configs for Node code (`api/`, `bin/`, `lib/`) and browser code (`frontend/`)

## CI

GitHub Actions runs on push to main and PRs to main/4.0.0: pnpm install → lint → build → test (Node 24.x). A separate release-please workflow handles versioning, changelog, GitHub releases, and npm publishing via trusted publishing (OIDC).
